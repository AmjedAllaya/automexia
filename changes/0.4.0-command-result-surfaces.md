# Make completed command output easier to distinguish

Completed output now receives a visible but restrained success/error-tinted
surface, a 2.4-3.5 pixel left rail, an adaptive 6-10 pixel visual breathing
gutter, an end rule, and the existing icon plus duration. The semantic owner
applies the same treatment to every proven result, including listing and
non-listing commands, success and error exits, single- and multiline output,
and deeply wrapped managed input. A newly completed live result lightens once,
holds for the first third of its 540 millisecond cycle, then eases out without
repeating, moving content, or restarting in scrollback.

A follow-up validation incident fixed PowerShell failures that could inherit a
stale successful native-process code. PowerShell result styling now uses its
immediate semantic success/failure state while preserving user-owned
`LASTEXITCODE`. Native Windows regression coverage now rejects stale result
surfaces, exercises five ordinary command shapes, checks real output-glyph
pixels, and directly compares blank surface pixels with the neighboring
background on both WGPU and the CPU fallback.

The treatment is renderer-only. It does not insert terminal rows, write PTY
input, or change selection, copy, search, history, reflow, and shell ownership.
A complete grouped surface currently requires integrated PowerShell, Bash, or
Zsh lifecycle markers; Fish and stock CMD fail closed without guessing.
