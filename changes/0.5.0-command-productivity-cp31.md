# CP3.1 persistent opt-in aliases

- Added dry-run-first `automexia aliases` list, preview, test, enable, disable,
  rename, regenerate, disable-all, rollback, doctor, and reload commands with
  source-revision and generation compare-and-swap protection.
- Added private immutable content-addressed five-shell generations, exact
  SHA-256 manifests, compiler identity verification, a nonblocking cross-process
  lock, a durable transition journal, source-CAS/pointer-last publication,
  deterministic all-old/all-new recovery, and one retained rollback generation.
- Extended the existing managed PowerShell, Bash, Zsh, Fish, and CMD adapters to
  verify and load one bounded artifact, reject unsafe permissions/links/tamper,
  recheck native ownership, retain last-known-good reload behavior, and perform
  no provider/network/action execution or canonical rewrite at startup.
- Kept manifest encoding deterministic and panic-free even under hostile parsed
  input; invalid completeness/order remains rejected before publication.
- Rejected non-digest rollback pointers before publication, recovery, disable,
  rollback, activation, cleanup, override reuse, or health checks.
- Tightened read-only verification so active and retained rollback generations,
  exact generation/shell directory topology, every artifact permission/ACL, and
  artifact source/shell/compiler metadata are checked even when SHA-256 matches.
- Made every preview and mutation dry run expose the reusable current source
  revision/generation, source digest, binding/tool/completion detail, collision
  owner, and exact owner fingerprint; doctor now reports malformed source and
  unsafe alias roots as stable health states instead of exiting.
- Cached executable identities and completion artifacts per unique observation,
  avoiding repeated large executable hashes across five shell projections.
- Kept native definitions authoritative. Authenticated exact-owner consent is
  reused only while the same observable owner fingerprint remains; unsafe-to-
  restore aliases/functions are never overridden.
- Made alias diagnostics strictly read-only and made disable/uninstall preserve
  canonical Quick Actions. Uninstall validates an exact bounded generated-state
  topology and refuses unexpected entries before changing profiles or state.
- Hardened fresh-shell idempotence markers and Zsh metadata/collision discovery;
  Fish uses one bounded fixed-path verification helper and a shell-native timing
  harness while retaining native-first and last-known-good behavior.
- Added focused transaction, crash recovery, tamper, contention, loader,
  collision, override, CLI, hostile-manifest, native lifecycle, startup p95,
  uninstall preservation/refusal, contract, mutation, and benchmark evidence.
- Bound all five native loaders to the exact ten-line
  `automexia-devops/0.4.0` manifest, added a last-known-good wrong-compiler
  regression, and made the full Bash/Zsh/Fish lifecycle an owned nightly and
  release WSL gate.
- Verified the release-profile 256-binding group locally: five-shell compile
  24.228-26.100 ms, durable publish/verify 35.476-37.391 ms, and read-only doctor
  8.580-9.228 ms. Exact topology, per-artifact ACL checks, and pre/post-mutation
  rollback-pointer validation remain enabled; the controlled 30-day baseline is
  still a release gate.
- Marked CP3.1 fully done at the source/local implementation boundary; CP3.2
  first-party packs, CP3.3 trusted bridges, hosted native release evidence, and
  the controlled named-hardware 30-day baseline remain separate gates.
