Added

- Add a bounded local image quick-look overlay: plain hover after a 100 ms
  stability delay, direct click-to-pin, wraparound arrow navigation between
  visible image paths, and Escape dismissal. Selection plus
  Ctrl+Alt+I/Cmd+Alt+I and the command palette remain keyboard paths. Terminal
  mouse-reporting mode keeps ownership unless Shift is held; decoding stays off
  UI/PTy threads, stale route generations are discarded, WSL paths are
  validated, and extreme panes hide rather than overlap the terminal.
- Preserve application-driven Sixel, Kitty Graphics, and iTerm2 inline images;
  harden iTerm2 raster decoding with encoded/declared-size, dimension, and
  allocation limits plus focused protocol regressions.
- Reject unsupported magic, changing files, and oversized dimensions before
  full decode; coalesce obsolete work behind a hard queue bound and deliver
  completion through generation-scoped per-window mailboxes.
- Reuse file-version-matched thumbnails in a 16-entry/32 MiB LRU and share the
  exact pixel allocation plus stable identity with Sugarloaf. A dedicated
  Criterion target measures cold decode/resize against warm validated reuse,
  and explicit-nightly fuzzing exercises the same bounded byte decoder. The
  contributor command routes Windows through supported WSL libFuzzer rather
  than depending on a missing native AddressSanitizer DLL.
- Isolate tokenization, bounded decoding, and thumbnail caching in the private
  renderer-free `automexia-image` crate. Nightly CI installs nightly explicitly;
  the supported local WSL campaign completed 544,609 decoder executions without
  a crash or sanitizer finding.
- Fix CPU-fallback compositing so positive-z image pixels are painted after the
  preview card/UI geometry instead of being hidden beneath its nearly opaque
  background. Preview titles now elide against measured remaining width rather
  than colliding with dimensions, and native WGPU plus CPU tests sample the
  image body itself to reject black or obscured previews.
- Add one required `cargo xtask test image-rendering` gate covering every
  enabled decoder, malformed/mutated inputs, exact alpha/byte accounting,
  bounded cache replacement, file-handle and sidecar-storage behavior, frontend
  lifecycle, Sugarloaf resource/draw-order, and protocol regressions. Its
  Windows native form repeats real WGPU/CPU open-dismiss cycles, requires zero
  active renderer/worker resources after dismissal, enforces process-growth
  ceilings, and compares backend pixel distributions. Fuzz builds now use
  disposable storage with explicit RSS/input-time bounds.
