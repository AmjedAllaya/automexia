# Multi-cloud stable-release assurance

- Bind AWS SSO login endpoints to the named or legacy public SSO region and
  reject ambiguous duplicate profile/session keys.
- Reject duplicate Azure JSON keys and duplicate or pre-section GCP INI keys;
  reject duplicate Azure CLI-version keys and align interactive login review
  with the official CLI platform default.
- Reserve a fresh private transient root and enforce capsule revision together
  with capsule, session, and generation on every transient handle use.
- Preserve private Windows ACLs and atomic recovery on validated local-drive
  paths beyond 260 UTF-16 units; normalize ordinary separators before verbatim
  API calls and reject relative or remote ACL namespaces.
- Reuse strict duplicate-key JSON decoding for AWS STS and Teleport status.
- Add a maximum AWS parser benchmark and a shared real-parser M8-M12 fuzz target
  with focused optional dependencies, hosted nightly execution, and a bounded
  Windows ASan campaign.
- Add a semantic M8-M12 contract checker with mutation tests, hosted CI/full-QA
  wiring, and provider-specific S1 native/resource/visual/accessibility gates.
- Make the stable-release failed-Git mutation deterministic even when its
  D-drive temporary directory is nested under the checkout.
- Keep all provider execution disabled and keep OpenBao unimplemented pending
  acceptance of ADR 0024 and its separate credential-custody boundary.
