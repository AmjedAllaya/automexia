# Project roadmap overview

This reader-friendly page summarizes the public [Automexia roadmap](../ROADMAP.md).
It does not contain the internal execution ledger and it never overrides source,
tests, feature documentation, or release evidence.

## Now

Automexia is focused on a stable, accessible, efficient terminal release and on
clear installation and onboarding. Command productivity, context visibility,
connection inventory, SSH foundations, and provider-neutral extension work need
their remaining native and release evidence before broader activation.

## Next

- Mature independently enabled DevOps/SRE connections and provider adapters.
- Make environment context and reviewed actions consistent across tools.
- Add bounded error-section navigation and later situation-aware production
  investigation without automatic execution.
- Deliver Automation Studio after the first stable release and before a
  video-editing extension.
- Strengthen sandboxing, provenance, permissions, disable, uninstall, and
  replacement before broad third-party extension distribution.

## Later

Evaluate specialized workflow extensions, including media and video, only after
the shared terminal, extension, DevOps/SRE, and editor foundations are mature.
Offer general LLM workflow automation solely through a separate optional
extension; the core and domain extensions remain useful without it.

Exact algorithms, provider playbooks, phase graphs, implementation maps, and
internal evidence ledgers are intentionally excluded under the
[public/private documentation policy](../PRIVATE-DOCUMENTATION-POLICY.md).

## Early DevOps and SSH delivery track

The public direction is a read-only connection foundation followed by reviewed
system OpenSSH sessions, typed connection automation, provider-neutral context,
and independently enabled cloud and orchestrator adapters. Every activation
remains subject to the core stabilization and native release gates above.
