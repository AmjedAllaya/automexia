# automexia-ssh-integration

Private, non-executing planning and scoped metadata contracts. Not an SSH client,
plugin, public SDK, process launcher, credential owner or activation path.

Native connection review remains in `automexia-connectivity`. The application
owns effects. The existing VT owns framing; remote CWD is connection-scoped and
cannot be converted into a local filesystem path by this crate. The candidate
shell resources each have one owner under `resources/` and are embedded at
compile time. The explicit application `+ssh` adapter owns execution; the
managed launch broker and read-only planning command remain separate.

The library also owns the opt-in temporary upload and discovery wire contracts.
Upload integrity, request/revision/context parsing and generated source remain
pure; file access, SSH execution, shell lifetime and the passive detector belong
to application adapters and the separate `automexia-ssh-helper` binary.

Run `cargo test --locked -p automexia-ssh-integration --tests` for model and property
contracts. The test-only exporter under `examples/` feeds actual generated bytes
to the existing QA process owner and controlling-PTY shell tests. It is not a
packaged application command and never executes SSH.

`resources/upload-posix.sh.in` and `resources/upload-powershell.ps1.in` are
generator inputs with typed placeholder tokens, not standalone shell scripts.
Their generated output is exercised by the native Bash, Zsh, PowerShell 5 and 7
transfer tests; ordinary shell resources remain subject to the repository's
shell syntax gates.

See [current scope and verification](../docs/SSH-INTEGRATION-LIBRARY.md) and
[ADR 0086](../docs/adr/0086-nonexecuting-ssh-planning-boundary.md).
